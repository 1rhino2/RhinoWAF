# RhinoWAF 1.0.6

**Release date:** September 2026

Bug fix release from a full read-through of the request path. Several of these
made the WAF unusable in front of a real app, so if you are on 1.0.5 this is
worth taking.

## Fixed

- **Form POSTs were dropped.** `sanitize.All` called `ParseForm` on every
  POST, which drained the body before the reverse proxy forwarded it. Every
  `application/x-www-form-urlencoded` request came back as a 502
  (content-length mismatch). The body is now snapshotted for inspection and
  put back intact.
- **Paths and headers were rewritten before proxying.** The same pass
  html-escaped the path and stripped SQL keywords, so `/update-profile`
  reached the backend as `/-profile` and tokens with `0x` or `--` in them got
  mangled. The WAF no longer mutates the request beyond removing control
  characters from the path and query. Detection (`IsMalicious`) is unchanged.
- **Hot reload never reloaded.** `ip_rules.json` changes were detected and
  logged as reloaded, but the underlying init was once-only so nothing
  changed. Reload now re-reads the file, and a broken file keeps the previous
  rules live instead of wiping them.
- **Fingerprinting locked out remote browsers.** The verification page posts
  to `/fingerprint/collect`, which was restricted to localhost. Any visitor
  not on the same box got stuck on "Verification Error". The endpoint is
  public now (still rate limited per IP). Same for `/csrf/token`.
- **CSRF was on by default with server-side tokens.** Unless your app
  already fetched and echoed the WAF's token, every non-exempt POST was a 403.
  CSRF is now opt-in under `csrf` in `features.json`.
- **Client IP was spoofable.** `X-Forwarded-For` was trusted from anyone, so
  one header bypassed bans, rate limits and challenge IP binding. Forwarded
  headers are now honored only from `server.trusted_proxies` (default:
  loopback and private ranges). `LocalhostOnly` uses the same logic, so a
  local proxy forwarding for a remote client no longer exposes `/metrics`.
- **Data race in geo lookups.** The CIDR cache was written under the read
  lock. Under load that is a concurrent map write panic.
- **Deadlock in IP rule validation.** `ValidateRequest` took the read lock
  twice; with a ban or save waiting in between, every request hung.
- **Per-IP tracker races.** Request and connection slices for one IP were
  mutated from concurrent requests with no lock. Entries now carry their own
  mutex.
- **Reputation re-block loop.** Once an IP's score crossed the threshold it
  was re-blocked and re-logged on every request forever. The block now
  expires like any other.
- **False positives on everyday traffic.** `/index.php`, `/files/document.pdf`,
  `?q=grant+writing+tips`, `?q=free+advice` (the old UTF-7 check matched any
  plus-encoded space before "ad"), `?q=difference+between+cats+and+dogs`,
  `?q=price>10.5 or free`, `${utm_source}`, `data:image/...`, `/profile:edit`,
  and `| identity` were all 403s. Each check was tightened to the actual
  attack shape; the benchmark suite still detects everything it did before.
  Executable extensions are still refused in upload filenames and form
  values, and decoys like `shell.jpg.php` are refused everywhere.
- **Demo handlers hijacked `/login` and `/echo`.** In single-backend mode
  those paths never reached your app. Everything proxies now.
- **`features.json` websocket section was decorative.** Enforcement used a
  hardcoded handler; the configured one is wired in.
- **Fingerprint cookie abuse.** An unknown cookie value was stored as a new
  fingerprint, so a client could grow the map by one entry per request. Only
  known hashes are accepted; anything else re-runs collection. The IP to
  fingerprint index also appended once per request and now dedupes.
- **`HTTP3_ENABLED=true` did nothing** because the config flag was hardcoded
  off. `/reload` now also reloads `backends.json` like SIGHUP does. Turnstile
  and hCaptcha verification calls use proper encoding and a 10 second
  timeout. Backend proxies have response header timeouts.

## Config

New fields, both optional and backward compatible:

```json
"server": { "trusted_proxies": ["10.0.0.0/8"] },
"csrf": { "enabled": false, "double_submit": false, "secure_cookie": false,
          "token_ttl_hours": 1, "exempt_paths": ["/api/webhooks"] }
```
