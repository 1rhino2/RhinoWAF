# RhinoWAF 1.0.5

**Release date:** August 2026

Stability and usability release. The big theme: you can run and configure
RhinoWAF without editing `main.go` and rebuilding. The config file that the docs
always pointed at is now real, and the server behaves properly under a process
manager.

## Highlights

- **features.json is wired up.** A new `waf/config` package loads
  `config/features.json` at startup and actually applies it: listen address,
  backend, challenge system, fingerprinting, websocket, server timeouts, and
  logging. Before this release the file existed and was documented but nothing
  read it.
- **Flags and environment variables.** `-listen`, `-backend`, `-config-dir`,
  `-log-dir`, `-features`, plus `RHINOWAF_*` env equivalents. Precedence is
  flag > env > features.json > default. No more hardcoded `:8080` / `./config`
  / `./logs`.
- **Graceful shutdown.** SIGINT/SIGTERM now drains in-flight requests (15s
  grace) instead of dropping them. Works cleanly under systemd.
- **Server timeouts.** The WAF's own listener sets read header, read, write, and
  idle timeouts plus a max header size, so it is not itself an easy slowloris
  target. Configurable under `server` in features.json.
- **Fail loud on bad config.** A malformed features.json, an out-of-range value,
  or an unknown field stops startup with a clear message instead of silently
  running with defaults. A missing file still just uses defaults.

## Fixes

- Backend-unreachable now returns `502 Bad Gateway` instead of a `200` body that
  clients mistook for a real page.
- `health` uptime formatting used a hand-rolled integer-to-string that produced
  garbage for values of 100 or more (for example 100+ day uptime). Replaced with
  `strconv.Itoa`.
- Version reporting is consistent again. `waf.Version` is `1.0.5`, the banner,
  `/health`, and proxy headers all agree, and CI stamps the real git tag into
  release binaries instead of a hardcoded `1.0.0`.
- Config loader tolerates a UTF-8 BOM.

## CI / release

- Releases are now cut on a `v*` tag push, not on every commit to main. This
  stops the stream of accidental patch releases and lets a tag mean something.
- Release binaries are stamped with the tag version via ldflags.
- Release notes are generated from the commit range since the previous tag.

## Config format note

`config/features.json` was slimmed to the sections that are actually applied
(server, backend, challenge_system, fingerprinting, websocket, logging). IP,
geo, rate-limit, and smuggling settings continue to live in
`config/ip_rules.json`, which is the authoritative file for those and supports
hot-reload. If you were carrying an old features.json with extra sections,
regenerate it from `config/features.example.json`.

## Install

```bash
go build -o rhinowaf ./cmd/rhinowaf
./rhinowaf -version
```

Or grab a prebuilt binary from the releases page.

## Verify

```bash
go test ./...
./rhinowaf -listen :8080 -backend http://127.0.0.1:3000
```
