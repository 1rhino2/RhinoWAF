# RhinoWAF 2.0.0

The big change is detection. The old `sanitize` layer was one long function of
`strings.Contains` checks with a binary block/allow answer and a tail of false
positives (`or true`, `url(`, `xmlns`, `\u`, `convert(`). 2.0 replaces it with a
real rule engine and adds persistence, so bans and challenge passes survive a
restart.

## Detection engine (waf/engine)

- Rules in a small text DSL (`*.rules`), compiled to operators over a
  transform chain, with anomaly scoring. Not SecLang, not Coraza, our own.
- Real detectors instead of substring greps:
  - a SQL tokenizer that folds to a fingerprint, so `' or 1=1--` blocks but
    `grant writing tips`, `drop off the kids` and `O'Brien` pass.
  - an HTML-aware XSS detector, so `<img src=x onerror=>` blocks but
    `url(image.png)`, `xmlns`, and `<p>hello <b>world</b></p>` pass.
  - path traversal, SSRF (decimal/octal/hex IP forms and metadata hosts),
    log4shell (`${lower:j}ndi:` unwrapping), a shell-command operator that
    needs a real metachar so `foo | identity` does not trip.
- A decode pipeline (url, html, js, css, utf8, base64, ...) where every step
  is one pass and double decoding is an explicit rule, so `%u`, `&#` and `\u`
  get decoded and inspected instead of blanket blocked.
- Per-argument anomaly scoring: one long legit value cannot stack notices into
  a block, but an attack sprayed across arguments still adds up.
- Every block carries evidence: which rule, which target, the matched bytes.
- JSON and XML bodies are inspected (the old code never looked at them).
- Bodies are bounded and re-attached whole, fixing a truncation bug where a
  chunked body over the inspect limit reached the backend cut short.
- Detect mode (global, per site, per rule) logs without blocking, for staging.
- Hot reload: `/reload` and SIGHUP recompile the rules and swap atomically; a
  bad rule file keeps the old set. `-check-rules` validates and exits, like
  `nginx -t`.

## Persistence (waf/state, waf/cookie)

- A single bbolt file (next to the logs) keeps auto-bans, the cookie signing
  key, and reputation. A missing or unwritable file just runs in memory.
- Auto-ban: repeated engine blocks from one IP earn a temporary ban that
  outlives a restart.
- Challenge passes are now signed cookies bound to the client /24 or /64, so a
  solved challenge survives a restart instead of being a forgeable in-memory
  token.

## Wired up

- `exemptions`: trusted IPs, CIDRs, user agents and paths skip rate limiting
  and the engine (still header-validated). Replaces the hardcoded trusted-UA
  list.
- `body_limits`: 413 before the backend reads an oversized body.
- `honeypot`: paths a real client never requests (`/.env`, `/.git/config`)
  ban on contact. Off by default with a starter list.
- Auto-ban and honeypot alerts fire through the existing webhook notifier.

## Removed

- `cors`, `cache`, `compression`, `rewrite`, `conditional`: proxy features,
  not WAF features, and none were wired. Gone.
- The `global_rules` block in `ip_rules.json` that was parsed and ignored is
  documented as such; the engine covers what mattered.

## Config

New sections in `features.json`, all wired and validated: `engine`, `state`,
`autoban`, `exemptions`, `body_limits`, `honeypot`, and
`challenge_system.pass_ttl_hours`. Old files still load; missing sections take
their defaults. See `config/features.example.json` and `docs/rules.md`.
