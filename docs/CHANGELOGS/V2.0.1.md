# RhinoWAF 2.0.1

A test-and-fix release. 2.0.0 shipped with three things the docs described
that the code did not do yet, and a proper test pass found one real bug.

## Now actually wired

- **Rules hot reload.** `config/rules.d/*.rules` and `rules_dir` are watched;
  a change, `/reload`, or SIGHUP recompiles the ruleset and swaps it
  atomically. A broken file keeps the last good set and logs the error.
- **`X-WAF-Detect` header.** In detect mode (global, per site or per path)
  a request the rules would have blocked goes through with the matched rule
  ids in this header, unless `explain_on_block` is `none`.
- **Per-vhost `engine` block.** A `backends.json` entry can carry
  `"engine": {mode, paranoia, threshold, disabled_rules, detect_rules,
  exclusions, paths}` and it applies on load and reload.
- **Response phase.** The 950xxx leak rules now run through the reverse
  proxy's ModifyResponse: sql errors, stack traces and private keys in a
  5xx body (configurable) are logged in `detect` mode (the default) or
  replaced with a 403 in `block` mode. gzip bodies are decompressed for
  inspection, `text/event-stream` is left alone.

## Fixed

- The json body walker hung forever on a body with more string leaves than
  `max_json_leaves`: it stopped recording but never consumed the rest, so
  the array loop spun. A 120KB body, under the inspect limit, could park a
  goroutine for good. Found by the new stress tests.
- `vhost.GetProxy` split the host on the first `:`, so an IPv6 literal like
  `[::1]:8080` looked up `[`. Uses `net.SplitHostPort` now.

## Detection

Measured against the seclists payload lists (see `waf/engine/seclists_test.go`,
run it yourself with a seclists checkout). Before and after this release:

| list | 2.0.0 | 2.0.1 |
|---|---|---|
| SQLi Generic-BlindSQLi (41) | 100% | 100% |
| SQLi quick-SQLi (77) | 74% | 95% |
| SQLi auth bypass (96) | 96% | 96% |
| NoSQL (22) | 27% | 73% |
| XSS PortSwigger cheat sheet (6047) | 100% | 100% |
| XSS payloadbox (2688) | 75% | 80% |
| XSS Jhaddix / BruteLogic / RSNAKE | 93 / 91 / 78% | 94 / 97 / 84% |
| LFI gracefulsecurity linux (881) | 43% | 100% |
| LFI Jhaddix (930) | 48% | 73% |
| command injection commix (8262) | 100% | 100% |
| template expressions (10) | 40% | 80% |
| XXE (51) | 55% | 63% |

The misses that remain are mostly list entries that are not attacks on their
own (`update`, `like`, `<test></test>`), plus some JS-context and
browser-quirk XSS vectors. Zero blocks on the non-attack part of the
"big list of naughty strings" (emoji, RTL, zalgo, unicode); every blocked
entry there is an actual payload from the list's injection sections.

New rules: double-encoded traversal (930110), os file paths (930130, 880
entries), nosql syntax (942620), hex-encoded declare/exec (942500), xml
entity declarations (944310), attribute and js-context xss breakouts
(941120, 941390), wider template-expression matching. The xss detector now
handles backtick-quoted attributes, control bytes inside url schemes, css
comments in style, and html5 abrupt comment closes. The sqli classifier
catches the `'-'` / `' or ''-'` reopened-string probes.

## Testing added

Fuzzers on every parser and detector (run 60s each, clean), a stress suite
(64KB args, 5000 fields, 200-deep json, 20000 leaves, 1MB chunked bodies,
null and percent floods), benchmarks, the seclists harness, and tests for
each of the four wirings above. Whole suite runs under the race detector.

## Performance

Microbench, one core, default rules: a browser GET with 5 params runs
through the engine in about 70us, a form login attack in 35us, a 100KB
json body in 7ms. That is up from 52us on the GET in 2.0.0, the price of
the eight extra rules. The proxy path itself does about 11.7k req/s at 50
concurrent on a laptop with the engine exempted; a single IP flooding it
gets rate limited long before the engine matters.
